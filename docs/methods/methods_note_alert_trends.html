Methodological Note — Alert Trends and Adequacy Analysis, EVD17 Response

Describing the implemented adequacy metrics and trend tests

Published

September 17, 2026

0.1 Purpose

This note documents the trend-analysis workflow implemented in R/02_alert_trends.R. It explains how the script turns the threshold synthesis from script 01 into weekly adequacy measures, smoothed counts, recent rankings, and Mann-Kendall trend tests.

The operational question is:

Are health zones generating the expected volume of validated alerts, and is that volume changing over time?

0.2 Data inputs

Input Source Role
Cleaned EVD line list Latest file under ../DataCleaning/data/Output/ Validated alerts from 2026 onward
Threshold synthesis table output/01_thresholds_synthesis.rds HZ- and window-specific threshold values

The script loads both inputs, keeps validated alerts only, converts notification dates to Date, and restricts the analysis to 2026 onward.

0.3 Alert counting and threshold joining

Validated alerts are joined to the threshold synthesis and summarised by time window (week start date) and health zone. The analysis keeps separate counts for case alerts and death alerts, and it derives a total_alerts series for trend testing.

The threshold columns are normalized to consistent names before adequacy is computed.

0.4 Alert Adequacy Index (AAI)

For each HZ and week, the script computes midpoint thresholds:

\[ T_{case}^{mid} = \frac{T_{case}^{lower} + T_{case}^{upper}}{2} \]

\[ T_{death}^{mid} = \frac{T_{death}^{lower} + T_{death}^{upper}}{2} \]

Adequacy ratios are then defined as:

\[ A_{case} = \frac{case\_alerts}{T_{case}^{mid}}, \qquad A_{death} = \frac{death\_alerts}{T_{death}^{mid}} \]

The Alert Adequacy Index is the mean of the available adequacy ratios:

\[ AAI = \text{mean}(A_{case}, A_{death}) \]

When no valid threshold midpoint is available, AAI is set to missing.

0.4.1 Interpretation

  • AAI = 1 indicates alert volume matches the threshold midpoint.
  • AAI < 1 indicates fewer alerts than expected.
  • AAI > 1 indicates more alerts than expected.

The script classifies adequacy using the following cut points:

Category Condition
Under-alerting AAI < 0.75
Adequate 0.75 <= AAI <= 2.0
Over-alerting AAI > 2.0

For the recent summary table, the script averages AAI over the most recent 3 weeks.

0.5 Temporal smoothing

The trend script applies a right-aligned 3-week rolling mean to case and death alerts within each HZ. This smooths short-term noise while retaining the current week in the rolling window.

The smoothed counts are stored as case_alerts_3w and death_alerts_3w.

0.6 Trend testing

The script applies the Mann-Kendall test to total_alerts within each HZ. The test is run only when there are at least 4 weeks with AAI data in the zone.

For each HZ, the script extracts:

  • Kendall’s tau
  • the p-value
  • a simple trend label:
    • Increasing: p < 0.05 and tau > 0
    • Decreasing: p < 0.05 and tau < 0
    • Stable: all other non-missing cases
    • Unknown: failed test or missing result

The same procedure is repeated for the most recent 6 weeks to capture short-term movement.

0.7 Recent adequacy ranking

For the most recent 3 weeks, the script computes mean AAI by HZ, assigns an adequacy category, joins the long-run trend labels, and sorts the result by mean AAI. This produces a ranking table that highlights HZs that are currently under-alerting or over-alerting.

0.8 Outputs

The script saves:

  • 02_trends_smooth.rds
  • 02_trends_smooth_adeq.rds
  • 02_recent_adequacy.xlsx
  • trends_smooth.xlsx
  • trends_smooth_adeq.xlsx
  • 02_alert_trends.pdf

The PDF includes an overall alert trend plot and a faceted view for the highest-priority under-alerting HZs.

0.9 Glossary

The column-level glossary for 02_trends_smooth_adeq.rds is included below.

1 Glossary — 02_trends_smooth_adeq.rds (English)

  • zone_sante_notification: Health zone name used for notifications.
  • Province: Province containing the health zone.
  • Population: Projected population for the health zone.
  • expected_weekly_deaths_cmr: Expected weekly community deaths from CMR.
  • death_threshold_lower_A: Baseline death threshold lower bound (Approach A).
  • death_threshold_upper_A: Baseline death threshold upper bound (Approach A).
  • alert_case_threshold_lower_B: Beni case benchmark lower bound (Approach B).
  • alert_case_threshold_upper_B: Beni case benchmark upper bound.
  • alert_death_threshold_lower_B: Beni death benchmark lower bound.
  • alert_death_threshold_upper_B: Beni death benchmark upper bound.
  • threshold_time_key: Threshold window identifier used when joining thresholds.
  • week_start: Week start date associated with the threshold window.
  • alert_case_threshold_C: Central case threshold from Approach C (case-derived).
  • alert_case_threshold_lower_C: Lower case threshold from Approach C.
  • alert_case_threshold_upper_C: Upper case threshold from Approach C.
  • alert_death_threshold_C: Central death threshold from Approach C.
  • alert_death_threshold_lower_C: Lower death threshold from Approach C.
  • alert_death_threshold_upper_C: Upper death threshold from Approach C.
  • Alert_case_threshold_lower: Synthesised case lower threshold (saved column name in trends object).
  • Alert_case_threshold_upper: Synthesised case upper threshold.
  • Alert_death_threshold_lower: Synthesised death lower threshold.
  • Alert_death_threshold_upper: Synthesised death upper threshold.
  • Alert_case_threshold: Final central case-alert threshold.
  • Alert_death_threshold: Final central death-alert threshold.
  • case_alerts: Observed number of validated case alerts in the week × HZ.
  • death_alerts: Observed number of validated death alerts in the week × HZ.
  • total_alerts: Sum of case_alerts and death_alerts for the week × HZ.
  • case_adequacy: Ratio of observed case_alerts to case threshold midpoint.
  • death_adequacy: Ratio of observed death_alerts to death threshold midpoint.
  • aai: Alert Adequacy Index — mean of case_adequacy and death_adequacy (when available).
  • adequacy_category: Category derived from aai for the current week (Under-alerting, Adequate, Over-alerting).
  • case_alerts_3w: 3-week right-aligned rolling mean of case_alerts.
  • death_alerts_3w: 3-week right-aligned rolling mean of death_alerts.
  • aai.3w: AAI computed using the 3-week smoothed alerts (averaging smoothed case and death adequacy).
  • adequacy_category.3w: Adequacy category computed on the aai.3w value.
  • total_alert_deaths: Total observed deaths per week × HZ, computed by applying alert_is_observed_death() (checks both nature_alerte and s6_statut_final_patient for “Décédé”) to validated alerts within each threshold time window. Broader than death_alerts which uses only nature_alerte variants.
  • adequacy_cmr: CMR adequacy — ratio of total_alert_deaths to expected_weekly_deaths_cmr. A value > 1 indicates more observed deaths in that week × HZ than the CMR baseline predicts.

1.1 Caveats and limitations

  • The AAI depends on the quality of the threshold synthesis from script 01.
  • Right-aligned rolling means introduce lag.
  • Mann-Kendall detects monotonic trends, not abrupt changes or seasonality.
  • The current adequacy thresholds are operational cut points, not formal clinical standards.
  • HZs with sparse data can have unstable trend labels.
